- [ ] **Worktree creation never bootstraps the new checkout** - createWorktree() (worktree.go:177) runs 'git worktree add' then TmuxNewSession then launches claude, and nothing else: no copying of gitignored-but-required files (.env), no install or build step. - [x] **Bus inbox replays the whole log to any new listener** - A fresh worktree has no seen cursor, so the SessionStart hook dumps the entire bus history at it: 958 messages in one case, more context than a whole session's real work. Three compounding causes. (1) Bus.Unseen("") returns everything (bus/bus.go:78-80) with no first-contact handling. (2) A cursor that is not found in the log does the same (bus/bus.go:88), so rotation or a trimmed store replays everything to an established session too. (3) buildInboxDigest (cmd_bus.go:272) is uncapped on the SessionStart/UserPromptSubmit path, which writes plain stdout; only the PostToolUse envelope caps at 10k. SeenKey() is the tmux session name (bus/sender.go:41-50), so every new worktree is a new key by construction. This bites every worktree-per-ticket build: each builder eats the full bus before it starts. Fix shape: treat a cursor miss as first contact, showing at most N recent and setting the cursor to latest immediately, plus a hard cap on the digest on every path rather than only PostToolUse. <!-- id:nly -->
